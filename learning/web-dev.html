Web & Mobile Development

Building software that runs in a browser or on a phone. The focus here is the web — HTML, CSS, JavaScript, and how a browser turns them into a page — with mobile treated as the place that work branches off.

What it is

Web development splits into the front end (what runs in the browser: HTML for structure, CSS for presentation, JavaScript for behaviour) and the back end (a server, a database, and the APIs between them). Mobile development is the same idea aimed at a phone: written natively (Swift for iOS, Kotlin for Android), with a cross-platform toolkit (React Native, Flutter), or as a web app wrapped for the app store. This site is itself a plain static web project — hand-written HTML and CSS, a little JavaScript, no framework — so it doubles as a worked example.

Why it matters

The browser is the most widely available runtime there is: one URL, any device, nothing to install. It's the shortest path from an idea to something a person can actually open and use. Learning it well also means learning the fundamentals — the request/response cycle, the DOM, layout, accessibility — that every higher-level framework is built on top of, and that carry straight over to mobile.

Key concepts

  • The three languages — HTML describes what content is, CSS describes how it looks and lays out, JavaScript makes it do things. Keeping those concerns separate keeps a project maintainable.
  • Semantic HTML & accessibility — using the right element (<nav>, <button>, <main>) gives you keyboard support, screen-reader meaning, and SEO for free.
  • The DOM — the browser's live, in-memory tree of the page. JavaScript reads and changes the DOM; the browser re-renders in response.
  • Responsive design — fluid units, flexbox/grid, and media queries so one layout works from a 360 px phone to a wide desktop. Mobile-first is the usual starting point.
  • Rendering strategy — static sites (HTML served as-is), single-page apps (JavaScript builds the page in the browser), and server-side rendering (HTML built per request). Each trades off speed, complexity, and interactivity.
  • HTTP — the request/response protocol underneath everything: methods, status codes, headers, and caching.
  • Tooling — package managers, bundlers, and frameworks (React, Vue, Svelte) speed up big apps; for a small site, plain files are often the right call.
  • The mobile branch — native vs. cross-platform vs. progressive web app; touch-first interaction, offline behaviour, permissions, and app-store review.

How it actually works

When a browser loads a page it fetches the HTML and parses it top to bottom, building the DOM tree and kicking off requests for CSS, JavaScript, and images as it finds them. CSS is parsed into the CSSOM; it blocks rendering until it's ready. The DOM and CSSOM combine into a render tree, then layout works out the size and position of every box, paint fills in pixels, and compositing assembles the layers (often on the GPU). JavaScript can change the DOM or styles at any time, which forces the browser to redo layout (“reflow”) and paint — so smooth pages minimise layout thrash and lean on cheap, compositor-only properties like transform and opacity. Native mobile apps skip the browser entirely and talk to the platform's own UI toolkit, but the mental model — a tree of views, a layout pass, an event loop — is the same.
